# 支付可行性调研

调研日期：2026-10-15。来源：支付宝 Agent 支付文档中心 `https://aipay.alipay.com/docs/llms.txt` 及其链接文档。以官方最新文档为准。

## 结论

1. **Agent 下单付款这条链路官方已经有标准做法**，和我们要做的事完全对得上。
2. **多商家各自收款**有现成的服务商模式（第三方应用 + `app_auth_token`），但个人商家能不能签、实物和预约能不能卖，还要再确认。
3. **黑客松阶段**：先用我们自己的收款账号作为第一家店跑通全链路；架构上按"每家店有自己的收款凭证"来设计。

## 1. 官方标准做法：商家接入 PC 端智能体

文档：`/docs/agent-pay/skillpay.md`，标题"商品和生活服务商户接入智能体平台"，适用场景原文：

> 商家之前在电脑网站经营，现在想让我的商品或服务可以被 PC 端 Agent 调用，在用户确认后使用支付宝完成支付。

流程：

1. 商家接入**电脑网站支付**（`alipay.trade.page.pay`）
2. 商家提供一个"**商家下单 Skill**"，由 Agent 唤起，负责选品、下单
3. 下单接口返回收银台链接后，调用 `alipay-bot trigger-payment-signal` 把链接压缩成支付短链
4. 调用 `alipay-bot submit-payment`，交给支付宝的支付处理 Skill，由它引导用户完成支付
5. 支付成功后，Skill 调用商家的结果接口完成交付

官方示例：`github.com/alipay/ai/tree/main/code_example/page-pay-demo-with-agentpay`（Node.js，星座运势）。示例里的下单接口是 `http://localhost:3000/pay`，说明**本地开发不需要公网**。不过支付宝的异步通知（`notify_url`）需要公网，本地开发时可以改为主动调用 `alipay.trade.query` 查询订单状态。

**对 OpenShop 的意义**：官方要求每个商家自己写这个"商家下单 Skill"。OpenShop 要做的，就是给每家店**自动生成**这个 Skill，并提供背后的下单接口。

## 2. 多商家收款的几种方式

| 方式 | 钱进谁的账户 | 适用商品 | 现状 |
| --- | --- | --- | --- |
| 第三方应用代调用（`app_auth_token`） | 商家自己 | 由商家签约的收单产品决定 | 智能体支付文档写明支持"第三方应用代调用"。商家需要自己签约电脑网站支付，再授权给我们的应用。个人能否签约、类目限制待确认 |
| 即刻收·平台模式 | 创作者自己 | **仅限数字权益**：买断、时长包、次数包、积分包 | 需要申请成为合作平台。**不适合预约和实物** |
| 平台统一收款再分给商家 | 先进我们的账户 | 任意 | **二清，不做** |
| 用我们自己的账号开第一家店 | 我们 | 任意 | 立刻可用；交易计入比赛统计 |

## 3. 其他事实

- 移动端智能体支付（`alipay.trade.agent.pay`）是给**智能体平台**（豆包这类）接入的，不是给商家的，**暂不支持沙箱**。和我们无关。
- 即刻收费率：JSAPI 0.6%–1% 加即刻收 0.4%。
- 首次签约收单产品未满 90 天的商家，资金次日结算。
- 文档站 `/docs/vibe-pay/ai-web-app-payment-qianyi/ai-web-app-payment-integration-guide` 页面目前挂错了内容（显示的是智能眼镜文档），电脑网站支付的签约细节需要去支付宝开放平台（`opendocs.alipay.com`）查。
