# 产品决策记录

2026-10-15 通过 grill-me 逐项确认。支付相关依据见 [payment-research.md](payment-research.md)。

## 一句话

给没有独立站的中小商家，配一个 agent 帮他们搭网站；每家店自动开放 MCP 和 Skill，让消费者的 AI agent 能直接查询、下单、用支付宝付款。

## 决策

| # | 问题 | 决定 |
|---|---|---|
| 1 | 目标商家 | 预约制服务（美甲、理发、私教、摄影……）和实物零售都做 |
| 2 | 商品模型 | 一套模型，用 `fulfillment` 区分：`booking`（选时间段）/ `shipping`（填地址）/ `pickup`（以后再做） |
| 3 | 店铺形态 | 托管店铺为主，加上可分享的链接和二维码；不做自部署。"店是商家自己的"指：钱直接进商家的支付宝、顾客数据归商家可导出、可绑自己的域名、不抽佣 |
| 4 | agent 怎么改网站 | 只改**结构化配置和业务数据**，不改代码，也不改表结构。网站 = 页面 JSON + 主题 + 业务数据，同一份数据同时驱动网站和 MCP。保留一个自定义 HTML 块作为逃生口。2026-10-21 重新讨论过“每家店一份前端代码、agent 改代码”的方案，仍然维持配置驱动；扩展方式见 tech-plan「模块怎么扩展」 |
| 4b | 商家自定义字段 | 参考 Shopify，分三种：**规格变体**（有独立价格和库存，如尺码、单人/双人）、**下单选项**（如辣度、刻字）、**展示信息**（如产地、教练简介）。所有店共用固定的表结构，用 `shop_id` 区分 |
| 5 | 第一版模块 | 店铺信息（必选）、商品/菜单展示、预约、购买、推广横幅、图文介绍/相册。支付和订单管理随交易模块自动带上，不单独勾选。推广横幅指商家自己的活动推广，不放第三方广告 |
| 6 | 商家开店流程 | 选行业、勾模块 → 填店名、电话、地址 → 立即生成带示例内容的网站 → 和 agent 对话替换真实数据，主路径是**拍照或截图导入**，识别结果须商家确认后才写入 → 绑定收款 → 上线。UI 留到做前端时再定 |
| 7 | 消费者的 agent 怎么接入 | 一个通用的 OpenShop Skill 加 MCP，底层是一套按店铺区分的 HTTP API。商家分享带店铺 ID 的链接，以后可以做跨店搜索 |
| 8 | 向商家收什么钱 | 免费开店，含全部基础模块和 agent 下单能力。专业版按月订阅，包括更多 AI 编辑次数、自定义域名、去掉 OpenShop 标识、高级模块，用 Token Pay 收。**agent 下单永远免费**，因为它是网络效应的来源 |
| 9 | 消费者身份 | 不建消费者账号。每家店按手机号自动积累**自己的顾客名单**。消费者的资料（称呼、手机号、地址）经同意后存在本地，由 Skill 自动带出。不用 agent 的访客直接在网页上下单，走同一套接口 |
| 10 | 订单处理 | 预约付款即确认；零售由商家手动点"已发货"并填快递单号。取消按商家设定的规则处理，规则内自动退款。通知走后台加浏览器推送（PWA）。商家的 agent 也能查订单 |
| 11 | agent 端的范围 | 第一版只支持桌面 agent（Claude Code、Codex、OpenClaw 等）。普通消费者用店铺网页。豆包、千问等 App 等它们开放后，再接同一套接口 |
| 12 | 参赛赛道 | 投 **Vibe Pay**（主赛道）。规则规定同一作品不得跨赛道重复投稿；Vibe Pay 奖项多，网页下单是主场景。agent 下单（Agent Pay）作为路演亮点，底层同样是电脑网站支付。接支付宝时按 Vibe Pay 的有效交易统计口径接入（2026-10-21） |

## 支付方案

- 消费者付给商家：电脑网站支付（`alipay.trade.page.pay`），加上官方的 agent 支付链路（`alipay-bot trigger-payment-signal` → `submit-payment`）
- 多商家收款：用服务商模式（第三方应用加 `app_auth_token`），钱直接进商家账户，不做二清。黑客松阶段先用我们自己的账号开第一家店
- 商家付给我们：Token Pay 连续订阅

## 端到端体验

1. **商家开店**：美甲店主选"美甲"，勾选预约、商品展示、推广横幅，填店名和电话，一分钟内看到带示例内容的网站
2. **导入数据**：拍一张价目表，agent 识别出 12 个服务项目及价格；店主确认后，网站和 MCP 同时更新
3. **改网站**：店主说"主色换成粉色，周末特价放到首页最上面"，agent 修改页面配置，立即生效
4. **分享**：店主把店铺链接发到微信群和小红书主页
5. **消费者下单**：顾客把链接丢给自己的 agent，说"帮我约周六下午做个法式"。agent 通过 OpenShop Skill 查到空档，带上本地保存的手机号下单，交给支付宝 Skill 付款
6. **商家收单**：店主手机上弹出推送；后台日历上出现这条预约，标着"来自 AI"；这位顾客自动进入店主的顾客名单

## 已知风险和待确认

- 个人支付宝账号签约电脑网站支付后，能否收实物和预约的款；服务商模式对我们应用的资质要求
- 拍照识别的准确率，尤其是手写价目表
- 消费者第一次使用要装 Skill、装 alipay-bot、开通 AI 钱包授权，共三步，需要尽量压缩
- 跨店搜索和店铺目录的冷启动
